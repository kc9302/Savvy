# 인스타 저장됨 대시보드 상품화 시뮬레이션 피드백

가상 인물 6명이 1라운드 독립 평가를 했다. 토론 라운드는 돌리지 않았다. 이 문서는 "무엇부터 점검할지"의 힌트이고, 수요나 지불 의사의 증거가 아니다.

## 1. 결론 표

| 항목 | 결론 |
|---|---|
| 지금 그대로 상품화 | 6명 전원이 이르다고 봄 |
| 유료(A) | 6명 전원이 반대하거나 보류. 약관 검토와 차단 위험 해소 전에는 비권장 |
| 가장 많이 나온 방향 | 개인용 유지(D)로 시작해 무료 오픈소스(B)로 가는 순서 |
| 크롬 확장(C) | 의견이 갈림. 쓰기 쉬워지지만 약관·스토어 심사·쿠키 접근 우려가 큼 |
| 수익 | 월 구독 지불 의사 없음. 낸다면 1회 결제 5천~2만 원대(추정, 인물 2명의 직감) |
| 핵심 병목 | 데이터 가져오기 마찰, 인스타 약관·계정 제재 불확실성, 비공식 경로 의존 |

점수 평균은 의미를 두지 않는다. 같은 모델이 만든 인물이라 점수가 비슷하게 수렴했다.

## 3. 전원 또는 다수가 동의한 것

1. 가져오기 마찰이 가장 큰 장벽이다. 콘솔 붙여넣기와 인스타의 해킹 경고 문구, 장시간 대기를 6명 모두 걸림돌로 꼽았다.
2. 인스타 약관과 계정 제재 가능성이 확인되지 않았다. 6명 모두 불안 요소로 꼽았다.
3. 비공식 경로는 예고 없이 막힌다. 이미 내부 API 한 곳이 404였다는 사실이 근거로 반복됐다.
4. 분류 정확도를 측정해야 한다. 눈으로 확인한 수준이라는 점을 5명이 지적했고, 못 나눈 항목을 "미분류"로 모아 한 번에 고치게 하라는 요청이 나왔다.
5. "데이터가 기기 밖으로 나가지 않는다"는 점은 호평이었다. 첫 화면에 크게 쓰라는 요청도 나왔다.
6. 월 구독은 아무도 내지 않는다. 한 번 정리하면 매달 쓸 이유가 약하다는 이유다.

## 4. 쟁점별 결론과 소수 의견

**쟁점 1. 크롬 확장(C)을 만들 것인가**
- 찬성: 서지윤, 박민재. 콘솔 붙여넣기를 없애는 가장 직접적인 방법이라고 봤다.
- 반대나 우려: 최도현은 확장이 계정 쿠키에 접근하는 게 더 불안하다고 했다. 정수아는 자동 수집이 더 노골적이라 스토어 심사 거절과 계정 제재 위험이 크다고 봤다(추정). 한승우와 윤하린도 심사와 약관 위험을 지적했다(추정).
- 정리: 쓰기 쉬움과 약관 위험이 맞교환이다. 검증 전에는 보류가 다수 의견이다.

**쟁점 2. 오픈소스(B)로 공개할 때 무엇을 올릴 것인가**
- 정수아는 공식 내보내기 파서 중심으로 올리고 스크래핑 코드는 분리하라고 했다.
- 정정: 시드 자료에 "공식 내보내기가 2,400개 중 33개만 담았다"고 썼으나 잘못이었다. 33개는 처음에 잘못 본 다른 계정의 내보내기였고, 2,436개는 지금 계정에서 긁은 수다. 지금 계정의 공식 내보내기는 아직 받아보지 못해 완전성을 모른다. 인물들이 "공식 내보내기는 쓸 수 없다"는 전제로 낸 의견(특히 VC와 개발자)은 그만큼 약하게 읽어야 한다.
- 최도현은 소스가 공개돼 있어 직접 읽고 네트워크 요청이 없음을 확인할 수 있어야 쓰겠다고 했다. 단일 HTML 구조와 맞는 장점이다.

**쟁점 3. 수익이 날 수 있는가**
- 한승우는 사업으로는 부업 수준이 상한이라고 봤다(추정).
- 서지윤과 윤하린은 1회 결제라면 5천~2만 원대를 낼 수 있다고 했다(추정, 직감).
- 소수 의견: 박민재는 어떤 형태든 돈을 내지 않는다.

## 5. 실행안 (제안)

1. 지금은 개인용으로 계속 쓰면서 아래 검증을 한다.
2. 분류 정확도를 표본으로 잰다. 직접 라벨링한 100개 정도로 정답률을 구해 화면에 보여준다. 그 뒤 LLM 분류와 비교한다.
3. 인스타 약관의 자동 수집 조항을 확인한다. 정식 판단은 변호사에게 받는다.
4. 공식 내보내기가 보통 얼마나 누락되는지 주변 저장량 많은 사용자 5명 정도의 데이터로 확인한다.
5. 위가 정리되면 무료 오픈소스로 소규모 공개한다. 스크래핑은 별도 선택 기능으로 분리하고 "본인 책임, 계정 제재 가능" 경고문을 붙인다.
6. 공개 후 반응을 보고 크롬 확장과 1회 결제를 판단한다. 통과·중단 기준은 공개 전에 미리 정해둔다.

## 6. 인물들이 확인하고 싶다고 한 것

- 노션 웹클리퍼, 레이인드롭 같은 기존 도구와의 차별점 한 문장
- 분류 정확도 수치와 틀렸을 때 고치는 방법
- 저장일이 없을 때도 쓸모 있는 차트
- 약관·계정 위험을 쉬운 말로 설명한 안내
- 이용자 데이터가 로컬에만 머무는지에 대한 명확한 고지

## 7. 한계

1. 같은 모델이 연기한 인물이다. 실제 사용자의 반응이 아니다.
2. 시드 자료의 구성이 결과를 기울인다. 약점을 명시한 만큼 약점에 집중했을 수 있다.
3. 시장 규모, 전환율, 지불 금액, 경쟁 제품 가격 같은 실제 데이터가 없다. "추정" 표시는 사실이 아니다.
4. 법무 의견은 영역 이름 수준이며 정식 자문이 필요하다.
5. 이 결과로 출시나 투자 결정을 내리지 않는다. 다음 단계는 실제 사용자 5~10명 인터뷰와 소규모 베타다.
